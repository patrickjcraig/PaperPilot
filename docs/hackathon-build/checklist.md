# PaperPilot Build Checklist

Status: Approved and locked for guided execution

Target: a public, hackathon-ready Tuesday candidate that proves PaperPilot's real WebMCP mentor loop over previously unseen admitted PDFs without weakening provenance, human decision authority, or accessibility.

Approved wow moment: a reader highlights difficult scientific material, the named browser agent autonomously invokes PaperPilot's bounded source-read and structured-stage tools, and PaperPilot displays the resulting research-mentor explanation beside an inspectable source → agent → human evidence trail. Figure and region understanding must be first class, but it does not replace the native text proof.

## Build Preferences

- **Build mode:** Autonomous
- **Comprehension checks:** N/A; explain consequential architecture changes in the build journal
- **Git:** Create a checkpoint commit after every green checklist item only after confirming that the PaperPilot checkout is the repository root; never stage or commit sibling directories from an enclosing worktree
- **Verification:** Yes; run focused checks for every item and stop for participant inspection only after items 2, 8, and 10
- **Check-in cadence:** Speed-run; report completed outcomes, failed gates, scope threats, and the next active item without waiting between ordinary green tasks
- **Scope changes:** Never silently cut an approved candidate requirement. Follow the Spec's safe cut order for optional work; request an explicit scope decision before removing exact text, visual selection, Connect ideas, the three follow-up intents, provenance, actor-private proposals, human decisions, public deployment, or accessibility.
- **Local development host:** The project owner explicitly chose a no-cost loopback workflow for active development: `127.0.0.1:3000`, a checkout-drive-scoped Prisma Dev database, and pgAdmin as a client of that same database. This local checkpoint may support implementation work, but it does not count as public HTTPS, production-role, container/worker, or judge-accessible release evidence. No paid VPS is required for development; a zero-cost public handoff remains a later explicit release decision.

Sizing note: the approved no-compromise scope is larger than twelve honest 15–30-minute tasks. These twelve entries are dependency-ordered, independently verifiable work packages; during `$build-project`, Codex must subdivide each package into 15–30-minute internal green/red cycles and journal those cycles without adding participant pauses beyond the three locked gates.

## Execution Rules

- Work in order. A red acceptance criterion blocks dependent items.
- Preserve existing user work and the older webpage-evidence integration; the Reader mentor tools are a separate bounded surface.
- Keep the browser agent as the only explanation engine. Do not introduce a server-side or in-product substitute model.
- Treat the named-client recordings as release evidence, not as automated-test substitutes. Automated browser tests use a controlled adapter and make no native-client claim.
- Use only the canonical tool names `paperpilot.read_sources` and `paperpilot.stage_explanation`; expose no Save, Discard, approve, or verify tool.
- Apply accessibility, actor authorization, source binding, and truthful activity semantics inside each vertical slice rather than postponing them to polish.
